# CLI packaging profiles for lsdtt3 backend bundles.
#
# One entry per line: <profile> <cli-name>. Blank lines and # comments are
# ignored. This file is the single source of truth for which CLIs ship in
# each bundle; it is read by tools/make_release.sh,
# tools/package_linux_backend.sh, tools/package_macos_backend.sh, and
# tools/package_windows_backend.ps1.
#
# Profiles:
#   qgis - the small subset wired into the QGIS plugin (Windows default)
#   core - tested tools shipped in official Linux/macOS releases (default)
#   all  - not listed here: means every lsdtt-* executable found in the
#          build directory that is also a current lsdtt_cli() target in
#          CMakeLists.txt (excluding lsdtt-test-*); local releases only
#
# Curation rule for `core`: a CLI belongs here when at least one CTest test
# exercises it. That is the file's definition of "tested" and it is checkable -
# cross-tabulate the lsdtt_cli() targets in CMakeLists.txt against tests/CMakeLists.txt.
# Adding a tool to core without a test is a decision to ship something the
# suite never runs.
#
# As of 2026-10-14 every lsdtt_cli() target has at least one CTest test and is
# in core. Eight were added that day: advection-diffusion, bankfull-width,
# cross-sections, marsh-topography, outlet-matching, slope-area,
# water-centreline and water-line-repair (four had been tested since
# 2026-10-07 but never listed here), and bearing-comparison and swath-profile,
# which had shipped untested, got their first tests. A new CLI joins core once
# it has a test; until then it ships only under `all`.
